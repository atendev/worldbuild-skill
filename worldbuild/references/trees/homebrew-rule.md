# Homebrew Rule / Game Mechanic

A tabletop rule that adds to or changes how the game is played, as opposed to lore. Covers small table rules, character-creation frameworks, and subsystems. A single player option (one subclass, one background, one item) is not this category; a rule that lets players *build* options is.

## Infobox fields

Shared Name/Status plus: **Status** uses proposed / playtesting / in use / retired. **System & edition**, **Rule type** (the type-gate below), **Replaces or modifies** (the official rule it changes, with book), **Applies when** (character creation, level up, combat, rests, downtime, always), **Inspired by** (port source, if any).

## Type-gate: Rule type

- **Table rule.** A small change to an existing procedure.
  - What exactly changes, in one or two sentences?
  - Which edge cases does the change create?
- **Character-creation framework.** A procedure players follow to build something.
  - What does it produce (a species, a background, a feat, a hybrid)?
  - What does the player choose from, and how many picks?
  - The step-by-step procedure, in order.
  - Power budget: what the result is worth against an official option of the same kind.
  - Restrictions: picks that are banned, required, or mutually exclusive.
  - Does the DM approve the result, and against what standard?
  - A worked example built with the procedure.
- **Subsystem.** A new mechanic with its own resource or tables.
  - What is the resource or state, and who holds it?
  - What triggers it, and what does spending or suffering it do?
  - Tables, if any.
  - How it recovers or resets.

## Branches (all rule types)

- Design goal: what problem at the table this solves, and how it should feel in play.
- Port or new: if porting, what the source rule did, what the new edition changed that breaks a straight port, and what to keep, drop, or rebuild.
- Balance: comparison to the official baseline, the worst abuse case, and where the cap sits.
- Interaction with existing house rules and homebrew (fact-find first).
- Edge cases and rulings worth writing down now.
- In the World: does the setting's lore explain or flavor the rule? Rules can stay generic while the lore notes what is common, rare, or unheard of.
- Player-facing vs. DM-only: which parts players read, and which belong in DM notes.

## Document sections (prose body)

Universal: **Summary** (player-facing, one paragraph), **Rule**, **Edge Cases & Rulings**, **In the World**, **Design Notes** (DM-only).

Character-creation framework additional: **Steps**, **Option Tables**, **Worked Example**.

Subsystem additional: **Tables**.
